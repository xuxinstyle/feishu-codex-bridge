# 飞书运行中任务停止功能设计

日期：2026-10-22。状态：已实现并通过本地验证；本机桥接已切换，飞书端可通过 `/panel` 获取新版卡片。

## 目标与语义

用户不用切换到 Codex 客户端，就能在飞书停止当前执行中的任务，保留同一会话的上下文，并在之后继续发任务。

按钮统一叫“停止当前任务”。停止表示结束本轮执行；“继续当前任务”是在同一会话发起新一轮继续请求，不承诺恢复到某条命令的执行位置。已完成的文件修改、提交和外部操作不自动撤销。

第一期只支持停止指定的一轮任务，不做全局停止、恢复执行快照或运行中自动改写任务。

## 当前实现与技术前提

- `bridge.mjs` 的 `cancelTask()` 对桌面通道的 `canCancel: false` 直接返回失败；目前只是提示用户到客户端停止。
- `codex-desktop.mjs` 通过客户端 App Tools 提交消息并读取状态。只读检查本机工具目录后，未发现停止、中断或暂停工具，不能假设存在某个可直接调用的停止方法。
- `codex-app-server.mjs` 的独立执行通道已经调用 `turn/interrupt`，但它不是默认的桌面执行端。
- Codex 官方接口允许按 `threadId + turnId` 请求 `turn/interrupt`，最终本轮状态为 `interrupted`；请求返回成功和最终确认停止应分开处理。[官方文档](https://learn.chatgpt.com/docs/app-server#interrupt-a-turn)
- 本项目此前已复现独立进程与客户端争用同一会话写入权限。因此不能另起 App Server 恢复桌面会话后，中断那个独立进程来代替停止客户端。

本轮已验证并接入客户端本地会话拥有者协议：连接 `codex-ipc`，先查询会话拥有者，再使用版本 4 的 `thread-follower-interrupt-turn` 和 `expectedTurnId` 中断指定轮次。没有创建第二个写入进程，也没有修改客户端安装文件。协议不可用时明确显示未确认，不结束整个客户端。该协议为客户端内部接口，兼容性变化需通过回归验证。

不采用结束整个客户端进程、模拟键盘焦点或把“停止”当普通模型消息作为默认实现。

## 推荐交互

### 执行中的任务卡片

把现有文本进度消息升级为任务卡片，主入口直接放在该任务的进度下，无需先打开 `/panel`。

```text
正在执行 · token_hub / 默认会话
任务：检查接口并运行测试
已用时：1 分 23 秒
待办：2 条

[停止当前任务]
```

第一期不加二次确认。点击后立即将按钮禁用，并显示“正在停止…”；后台再请求真正的中断。群聊沿用现有机器人接收消息与授权规则。

### 文字命令

| 输入 | 行为 |
| --- | --- |
| `/stop`、完整消息“停止”或“停一下” | 停止当前飞书聊天、项目、会话中的运行任务 |
| `/stop task-xxxx` | 停止指定且属于当前授权聊天范围的任务 |
| `/cancel task-xxxx` | 兼容旧命令：排队任务取消排队，运行任务走同一停止流程 |
| `/resume`、完整消息“继续” | 在同一会话继续最近一次停止的任务，创建新一轮执行 |

中文快捷语只做完整消息匹配，不用关键词包含匹配；“不要停止”“为什么停止了”“任务暂停机制怎么实现”等普通内容不会触发停止。第一期不把“暂停”作为快捷语，避免误导为可原地恢复。

无任务执行时回复“当前会话没有正在执行的任务”；不自动停止其他会话中的任务。

### 停止后的反馈

```text
已停止当前任务
会话上下文和已完成的改动已保留。
待办 2 条，已暂停执行。

[继续当前任务] [查看待办]
```

“查看待办”中可以取消单条待办，或选择“按顺序执行待办”。第一期不提供一键清空全部任务。

**停止本轮时，同时暂停该会话后续队列，保留待办内容。** 否则刚停止旧任务，下一条排队任务就会自动执行，与用户预期不符。其他会话不受影响。

“继续当前任务”优先运行继续请求，原待办继续保持暂停。停止后用户发送新的普通任务，也优先执行这条明确的新请求，并提示“旧待办仍暂停”；不会自动重放旧待办。

## 控制流程与状态

停止命令经过授权校验后，直接进入控制通道，不放到普通任务队列，不等待模型完成，也不等待项目列表刷新。

```text
用户点击停止
  → 校验任务及当前执行轮次
  → 暂停该会话待办队列
  → 显示“正在停止…”
  → 向拥有该轮任务的执行端请求中断
  → 收到目标轮次 interrupted 状态
  → 显示“已停止”，保留上下文
```

任务状态增加 `stopping` 和 `interrupted`。待办队列的 `paused` 独立于任务状态，不能把运行中任务直接标为 `cancelled`。

- 接口接受请求后仍是“正在停止”，只有确认目标轮次中断才显示“已停止”。
- 超过目标等待时间仍未确认，显示“暂未确认停止”，提供重查入口；不谎报成功，不自动结束整个客户端。
- 若目标轮次已正常完成，则显示“任务已完成，无需停止”，保留真实完成状态。
- 用户在客户端点击停止，也应同步显示“已停止”，不把 `interrupted` 当执行故障。
- 已提交但尚未识别到 `turnId` 时，记录停止意图；只中断随后确认属于本次提交的轮次，不能选择“最新一轮”猜测目标。

## 改动范围

| 位置 | 设计改动 |
| --- | --- |
| `bridge-core.mjs` | 新增停止/继续命令解析、完整中文快捷语匹配、状态判断 |
| `bridge.mjs` / TaskRunner | 新增异步停止控制，记录当前 `threadId`、`turnId`、执行代次；处理真实停止状态 |
| 会话队列 | 将不能暂停的 Promise 链改为可暂停调度，显式维护活动任务和待办列表 |
| 任务进度卡片 | 新增停止按钮、停止中/已停止反馈、继续和待办入口 |
| `codex-desktop.mjs` | 接入已验证的客户端中断能力，提供本轮开始及本轮中断的状态回调 |
| `codex-app-server.mjs` | 统一中断请求与最终确认语义，保留独立通道兼容性 |

适配层已增加 `interrupt(threadId, turnId)` 与停止状态确认。它使用客户端本地会话控制协议，不是 App Tools 工具目录中的某个停止工具。

任务卡片携带 `taskId` 和执行代次；实际目标以服务端记录为准，核验聊天、项目、会话和轮次。重复点击复用同一停止请求。旧卡片不得停止后来启动的新一轮任务。

任务卡片应按任务独立校验，不复用当前只允许“最新面板卡片”生效的全局面板校验规则，避免用户打开面板后，仍有效的任务停止按钮失效。

停止请求和当前任务状态的更新需要按会话串行协调，但中断请求不能阻塞在执行任务的队列中。先冻结队列，再请求中断，处理停止与正常完成同时发生的竞态。

暂停标记及停止请求关联信息可持久化，重启后先与客户端状态核对，不自动重发原任务。现有待办内容的宕机恢复不列入本期承诺。

## 实施顺序与验收

1. **能力验证**：客户端正在执行的测试轮次能被桥接真正中断；客户端与飞书观察到同一轮停止，之后同一会话可以继续聊天。不通过则先解决桌面接口问题，不发布不可用的停止按钮。
2. **核心交互**：实现进度卡片停止按钮、`/stop`、停止状态确认和会话队列暂停，兼容 `/cancel`。
3. **继续与完善**：实现继续当前任务、查看待办、跨端状态同步和竞态回归测试。

验收覆盖：运行中停止、提交中停止、排队任务取消、停止后不自动执行下一条、重复点击、旧卡片、停止与正常完成同时发生、客户端手工停止、停止请求超时、跨聊天/会话隔离、桥接重启后核对状态。

按钮回执目标为约 1 秒内呈现“正在停止”，真实结束时间取决于执行端及工具退出行为。测试须包含正在运行工具的场景，不能只测模型生成文字或桥接停止等待回复。

后续可独立增加 `/steer 补充要求`，用 `turn/steer` 向正在执行的轮次追加要求，不中断任务；它与停止是两项不同能力，也需要桌面执行通道支持。[官方文档](https://learn.chatgpt.com/docs/app-server#steer-an-active-turn)


## 实施与验证记录

- 真实桌面任务经桥接发起，停止后约 1.3 秒确认本轮中断；旧待办保留且未执行，随后在同一线程成功接收新任务并返回回复。验证使用本地模拟飞书信使，没有向真实飞书聊天发送测试消息。
- 运行命令测试另外确认：本轮中断不保证结束已经启动的独立命令进程。对客户端原生用户停止协议的对照测试也出现相同行为。因此产品只承诺停止当前轮次；后台命令或服务需要单独管理，不能把“已停止”解释为系统所有子进程结束。
- 飞书卡片使用同一渲染器生成预览；手机宽度 390 像素下检查了任务、停止反馈和设置页，没有横向溢出。预览是布局模拟，最终样式仍以飞书客户端为准。
- 首页移除了完整路径、任务编号、最近任务重复信息和全部模型按钮；模型与推理强度收进设置，项目与模型列表支持分页。每行最多两个按钮，停止不弹多余确认框。
- 预览入口：`npm run preview:cards`；生成 HTML 可独立打开。

- 最终本地自动化检查共 111 项通过，涵盖停止重试、结束竞态、过期卡片、队列隔离、模型设置变化和图片任务继续。
